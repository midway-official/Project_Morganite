# Proposed interconnect and LSU for the 16-SM GPU

[简体中文](16sm-noc-lsu.md) · **English**

The current board uses a shared 32-bit AXI4 path. The proposed first implementation groups 16 SMs into four clusters, each with four SMs, and connects a two-level memory tree to one dedicated 256-bit GPU AXI4 master. Keep the ISA, 32-bit device pointers, 8-thread warps, four physical lanes, 32-bit host AXI4-Lite page, 100 MHz CPU/GPU and 225 MHz HBM AXI. A later configuration adds a second independently scheduled port. Depths and targets below are design candidates.

## Tree or ring

Data, instruction refills and descriptor traffic converge at memory. Scratchpad stays local. In the shipped RTL all warps in an SM share gather/send/wait/writeback, global and local memory share that state, and load writeback blocks other warp issue. At the DMA there are 33 sources and one owner per direction. A cluster tree combines 32-byte line traffic locally and routes tagged replies through two arbitration levels. A four-cluster ring is a useful physical comparison if placement dominates. Its single memory endpoint concentrates traffic on nearby links and adds hops to short reads. Use separate request and response rings, per-hop credits and a reserved bubble or an escape channel with a deadlock argument. Compare equal ports, link width and total buffering. [SM](../src/main/scala/morganite/Sm.scala) · [DMA](../src/main/scala/morganite/Dma.scala)

The routed fault-to-SM10 path took 9.534 ns, including 8.553 ns of routing and three SLR crossings. Worst setup/hold margin was +0.062/+0.007 ns, worst hold in CPU LSU. Register cluster stop signals, capture the first fault locally, reject new DMA admissions after a fault and drain accepted work. Register backpressure at cluster boundaries. Use routed congestion and CPU hold to guide floorplanning. [Timing](u50c-16sm-20261124/physical/timing_impl.rpt)

## Request and response contract

A local arbiter accepts four data and four instruction sources. The root arbitrates clusters and descriptor traffic by address and source. Read headers contain address, operation, length and tag. Writes also carry 256 bits and 32 byte enables. Buffer read returns and store completion separately. Start with two-entry elastic FIFOs at arbitration boundaries. Reserve reply capacity before accepting reads and data/completion capacity before writes. Bound long-write service and provide progress for refills/descriptors even if an SM stalls on RF writeback.

Internal tags identify job generation, cluster, SM, class, LSU slot and subrequest. An external ID is local to an AXI port; store source tag, remaining beats and error in its table. Recycle read ID after RLAST, write ID after B and LSU slot after all subrequests and writeback/discard. Start with 8 outstanding reads and 4 writes; compare read depths 1, 4, 8 and 16. Approximate required depth from target bytes/cycle × measured round-trip cycles ÷ useful bytes/burst.

Accept interleaved responses across IDs and ordered responses within an ID. AXI4 W has no ID. Keep W bursts in queued AW order and make AW/W VALID independent of READY. Reserve space for delayed R/B. The current bridge is ID-less on its wide side. Check generated CDC/protocol IP for supported IDs, AXI3 WID, 16-beat splitting and aggregated B completion. A sequential bridge first needs same-ID pipelined characterization. [Board inputs](u50c-16sm-20261124/artifacts/soc-inputs.tar.gz)

## LSU changes

1. Start with two global instruction slots per SM; compare four. Keep one outstanding memory instruction per warp. Record warp, destination, active mask, size/sign, completions, fault and returned data. Gather addresses through the existing four lanes in two cycles, then allow another warp to gather. The issuing warp remains locked until completion. Give scratchpad independent admission. Preserve barrier, fence, exit and cancellation drain rules.
2. Choose the first active lane's aligned 32-byte line, group matching lanes and record per-lane byte offset/size. Repeat for remaining lines. One aligned eight-word vector takes one beat. Broadcast identical reads and use exact WSTRB for sparse stores. Preserve existing lane order for overlapping bytes. Start with independent warp coalescing, then compare multi-line bursts for explicitly contiguous transfers.
3. Precheck **all active lanes before any substore**. Retain carry and final-byte precision for bounds, alignment, code and read-only protection. Only expand an authorized read to a complete aligned line when the whole line is accessible. At partial windows use a verified narrow path or defined fault. Split at 4 KiB, window and HBM port boundaries.
4. Keep one BRAM RF write port. Buffer load results per slot, split into four-lane writebacks. Fixed-latency ALU/FMA cannot stall arbitrarily at retirement. Reserve writeback cycles at issue or inhibit new arithmetic for a bounded interval, drain earlier writes and admit the load. Unlock on the final committed slice. Measure lost issue cycles and prove forward progress.
5. First route existing I/D L1 and bypass paths through the tagged endpoint. Later group active lanes by actual line, tag misses, queue bypasses independently, then evaluate a second miss slot and same-line merging only for immutable data. Drain before invalidation at job boundaries. Compare same-bank/same-word scratchpad broadcast for N-body with per-lane byte selection. ## Implementation gates

| Stage | Deliverable | Required evidence |
| --- | --- | --- |
| 1 | Separate host/GPU width, port count and outstanding limits in GpuParams, Generate, Board and stage_soc. Extend sim/gpu.cpp. | Original 32-bit regressions, 1/2/4/16-SM legality, fixed binaries and immutable window. |
| 2 | Native wide endpoint; retain one slot and one outstanding per direction. CPU/JTAG on SAXI_00, dedicated GPU port. | All 256 lane masks, byte strobes, no side effects on invalid addresses, 8×FP32 in one beat. |
| 3 | Cluster tree, response routing, 8R/4W transaction table. | AXI ID reordering, prolonged stalls, independent AW/W, SLVERR/DECERR, cancellation, exactly one completion and bounded arbitration. |
| 4 | Multiple LSU slots, L1 wrapper, return and RF arbitration. | Compare 1/2/4 slots; RAW/WAW, store→load, barriers, partial warp, FMA contention and at least two concurrent requests from one SM. |
| 5 | Route and boot one-port SoC. Reuse existing CPU exchange window. | Clean 100/225 MHz routing, setup/hold, DRC/CDC and resources per SLR for CPU/GPU/SoC. Cross-agent visibility, independent JTAG traffic, consecutive jobs, output and device cycles. |
| 6 | Route any legal SM request by address to two ports with independent queues. Extend driver allocation and transfer ABI for additional HBM regions. | Compare one PC vs two PCs, cross-port same-address visibility, write drain and CPU/JTAG readback. |

The current coherent 2 MiB window is entirely in PC0. The diagnostic selects 16 × 256 MiB regions using address bits 31:28. Verify port mappings on hardware before splitting buffers. Extra HBM may be staged via the existing CPU exchange buffer. Direct CPU access needs verified LA32R addressing, uncached mappings, alias exclusion and allocator isolation. [Observed mapping](u50c-16sm-20261124/results/board-01/dma-mapping.json) · [PC diagnostic](../baseline/runtime/hbm_diag.tcl) · [AMD PG276](https://docs.amd.com/r/en-US/pg276-axi-hbm)

Count AR/AW, R/W handshakes, useful WSTRB bytes, first-data latency, depth, stalls and per-cluster waits at both clock domains with synchronized snapshots. Count LSU-full, pending return, writeback stalls, lines/warp and bank conflicts. One port at 100 MHz has a 3.2 GB/s directional ceiling; its HBM-side interface at 225 MHz has 7.2 GB/s. A candidate initial target is 1.6 GB/s sustained one-way over at least 1 MiB with verified data. Measure useful request rate/latency for sparse gathers. Compare identical binaries, masks, RO windows and frames. Current optimized GPU baselines are 42.02 ms for ray tracing and 928.51 ms for Mandelbrot. Optimized Julia and N-body still need complete board results. Test each change separately. High data-beat occupancy, queues and independent PC traffic justify a second port; idle data cycles with occupied LSU slots direct attention to concurrency and returns.
